## Dragonboon · Reusable tools for Godot

[**Dragonboon**](https://github.com/Dragonboon) is where game-development tooling comes together: independently usable addons, gameplay building blocks and procedural content tools. The goal is to solve a specific problem without forcing developers to adopt an entire ecosystem.

| Project | Focus | What it does |
| --- | --- | --- |
| **[Nucleus](https://github.com/Dragonboon/Nucleus)** | Foundation · Architecture | Composable Godot services and systems for new or existing games. |
| **[GodoForge](https://github.com/Dragonboon/GodoForge)** | Plugin development · CI | Reproducible starter template for creating, testing and shipping Godot addons. |
| **[Atrium](https://github.com/Dragonboon/Atrium)** | 3D · Level design | Room, dungeon and multi-floor architectural blockouts with editable Godot output. |
| **[Trispark](https://github.com/Dragonboon/Trispark)** | Match-3 · Gameplay | Configurable boards, input styles, matching rules and game reactions. |
| **[Deckit](https://github.com/Dragonboon/Deckit)** | Card games · Systems | Reusable cards, decks and zones, with optional actions, effects and turns. |
| **[JigsawG](https://github.com/Dragonboon/JigsawG)** | 2D · Puzzles | Procedural jigsaw puzzles with connected piece groups and configurable interactions. |
| **[Terrainy](https://github.com/Dragonboon/Terrainy)** | 3D · Procedural terrain | Noise-driven terrain generation and configurable landforms. |
| **[Pixel Sprite Monster Generator](https://github.com/Dragonboon/pixel-sprite-monster-generator)** | Pixel art · Procedural generation | Seeded creature sprites, palettes and PNG export. |
| **[Pixel Space Background Generator](https://github.com/Dragonboon/pixel-space-background-generator)** | Pixel art · Procedural generation | Reproducible stars, planets and nebulae for 2D backgrounds. |

## Engineering principles

**Learn deliberately.** New technologies are tools to understand, not labels to collect.

**Keep components focused.** Prefer clear responsibilities, composable systems and explicit boundaries over unnecessary abstractions.

**Automate what is repeatable.** Tests, validation, scripts and documentation should make future changes safer.

**Make work useful to others.** Good developer tools should be approachable, documented and honest about their current limitations.
